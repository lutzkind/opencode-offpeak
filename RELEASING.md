# Releasing

## Current public distribution

`v0.1.3` is complete and publicly installable from its exact GitHub tag with OpenCode CLI v2:

```sh
opencode plugin add git+https://github.com/lutzkind/opencode-offpeak.git#v0.1.3
```

`v0.1.0`, `v0.1.1`, and `v0.1.2` remain available at their own tags, but `v0.1.3` is the canonical release: it adds peak-aware retry recovery (a retryable provider failure during peak is stopped before it reaches the provider and the same session continues at the next off-peak window) on top of the v0.1.2 interactive boundary hold, the v0.1.1 compatibility enforcement, the documented `Plugin.define(...)` TUI shape, `/offpeak remove`, and the real-TUI regression smoke test. OpenCode officially accepts npm-compatible Git package specifications, including GitHub URLs and exact tags ([plugin installation docs](https://opencode.ai/v2/docs/plugins)). This install path loads both the server and TUI entrypoints. npm publication is optional future distribution; npm login, 2FA, or registry publication is not required before this release can be installed or used.

## Optional npm distribution

The package may be published to npm in the future if a maintainer chooses to add that distribution channel. Its absence does not block this release or require any user action.

For a future npm bootstrap, first confirm that the desired package version is absent, then publish reviewed package contents through an authorized npm maintainer account. Never commit or add an npm token to GitHub Actions. After the package exists, configure npm trusted publishing for:

- Package: `opencode-offpeak`
- Provider: GitHub Actions
- Repository: `lutzkind/opencode-offpeak`
- Workflow: `publish.yml` in `.github/workflows/`
- Permission: direct `npm publish`

The one-time CLI form is:

```sh
npm trust github opencode-offpeak \
  --file publish.yml \
  --repository lutzkind/opencode-offpeak \
  --allow-publish
```

Only after the package and trusted publisher are configured should the repository Actions variable `NPM_TRUSTED_PUBLISHING` be set to `enabled`. Without that explicit opt-in, `.github/workflows/publish.yml` skips its publish job on every GitHub release. This workflow stores no long-lived npm credential. A future stable release whose tag matches `package.json` will run lint, typecheck, tests, packaging, and the version check before publishing through GitHub OIDC; public npm provenance is generated by npm when supported.

Do not create another package version or GitHub release merely to test the optional channel. npm versions cannot be reused. Before any future npm release, check registry state, package contents, version/tag consistency, trusted-publisher configuration, and then verify registry readback and a clean consumer install.

## GitHub release checklist

For a new release:

1. Update `package.json` and `CHANGELOG.md` together.
2. Run `npm ci`, `npm run lint`, `npm run typecheck`, `npm test`, and `npm pack --dry-run`.
3. Merge the reviewed change to `main` and wait for application and repository-standard CI.
4. Create a version tag matching `package.json` and publish its GitHub release with notes and the reviewed tarball.
5. Verify the release tag, asset digest, installation through `opencode plugin add`, and `/offpeak status` in a clean OpenCode v2 configuration.
6. If npm distribution has deliberately been bootstrapped, verify the trusted OIDC workflow and npm registry readback separately.
