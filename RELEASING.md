# Releasing

## Current public distribution

`v0.4.4` is complete and publicly installable from its exact GitHub tag with OpenCode v2:

```sh
opencode plugin add git+https://github.com/lutzkind/opencode-offpeak.git#v0.4.4
```

`v0.1.0` through `v0.4.3` remain available at their own tags. `v0.4.4` is the
canonical release: it keeps every v0.4.x feature and records the verified
server/TUI range `>=2.0.26 <2.5.0` against both OpenCode 2.4.0 and the current
2.4.1. The 2.4.1 SDK adds only plugin automation hooks and lowers the OpenTUI
peer floor; every surface this package uses is unchanged. The Desktop GUI
entrypoint is built and validated against the installed 2.4.1 GUI API. It
keeps the shared canonical `/offpeak protection global` and
`/offpeak protection chat` commands, the native Desktop composer slash command,
the two independent persistent client defaults, the explicit
`session-overrides-v1` chat override, background-compaction coverage, the
read-only canonical `pricing` RPC consumed by `opencode-free-first` `peak-only`,
and the committed `dist/gui-experimental.cjs` bundle for bare git-tag installs.

Desktop users must also list the same tag in Desktop's own
`opencode.json(c)`; installing it only on the remote server enforces pricing
there but does not deploy the local GUI. The Desktop app must be 2.3.0 or newer; this release validates its slash command and title APIs against 2.4.1. The validation covers the real
packed-plugin TUI load and `/offpeak status` on both hosts, the packaged
Desktop GUI bundle smoke test, the full deterministic suite, the
zero-paid-traffic CLI/Desktop peak fixture run and real-TUI client test, and
the live install. OpenCode officially accepts npm-compatible Git package
specifications, including GitHub URLs and exact tags
([plugin installation docs](https://opencode.ai/v2/docs/plugins)).
This install path loads the server and TUI entrypoints; the same package supplies `./gui-experimental` to Desktop when Desktop lists it. npm publication is
optional future distribution; npm login, 2FA, or registry publication is not
required before this release can be installed or used.

## Optional npm distribution

The package may be published to npm in the future if a maintainer chooses to add that distribution channel. Its absence does not block this release or require any user action.

For a future npm bootstrap, first confirm that the desired package version is absent, then publish reviewed package contents through an authorized npm maintainer account. Never commit or add an npm token to GitHub Actions. After the package exists, configure npm trusted publishing for:

- Package: `opencode-offpeak`
- Provider: GitHub Actions
- Repository: `lutzkind/opencode-offpeak`
- Workflow: `publish.yml` in `.github/workflows/`
- Permission: direct `npm publish`

The one-time CLI form is:

```sh
npm trust github opencode-offpeak \
  --file publish.yml \
  --repository lutzkind/opencode-offpeak \
  --allow-publish
```

Only after the package and trusted publisher are configured should the repository Actions variable `NPM_TRUSTED_PUBLISHING` be set to `enabled`. Without that explicit opt-in, `.github/workflows/publish.yml` skips its publish job on every GitHub release. This workflow stores no long-lived npm credential. A future stable release whose tag matches `package.json` will run lint, typecheck, tests, packaging, and the version check before publishing through GitHub OIDC; public npm provenance is generated by npm when supported.

Do not create another package version or GitHub release merely to test the optional channel. npm versions cannot be reused. Before any future npm release, check registry state, package contents, version/tag consistency, trusted-publisher configuration, and then verify registry readback and a clean consumer install.

## GitHub release checklist

For a new release:

1. Update `package.json` and `CHANGELOG.md` together.
2. Run `npm ci`, `npm run lint`, `npm run typecheck`, `npm test` (which builds `dist/gui-experimental.cjs`), and `npm pack --dry-run`.
3. Rebuild `dist/gui-experimental.cjs`, verify `git diff --exit-code -- dist/gui-experimental.cjs` after `npm run compile`, then commit the changed bundle with the source; CI enforces this.
4. Merge the reviewed change to `main` and wait for application and repository-standard CI.
5. Create a version tag matching `package.json` and publish its GitHub release with notes and the reviewed tarball.
6. Verify the release tag, asset digest, installation through `opencode plugin add`, and `/offpeak status` in a clean OpenCode v2 configuration. For Desktop, verify `dist/gui-experimental.cjs` is present in the installed tag too.
7. If npm distribution has deliberately been bootstrapped, verify the trusted OIDC workflow and npm registry readback separately.
