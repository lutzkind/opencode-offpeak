# v0.5.1 — A settings change wakes every location

## What changed

OpenCode loads one plugin setup per project directory. The typed RPC has no
location selector, so a command that turns protection off can be handled by a
different engine than the one holding the request. In v0.5.0 that engine
updated shared storage but only woke itself; the holder kept its in-memory
copies until the next off-peak boundary, so a held request looked stuck even
though `/offpeak status` already reported `protection: OFF`.

Every engine now subscribes to a process-wide settings-change signal and
re-reads both the client document and the per-chat override document after a
wake. A switch to `OFF` therefore commits the same held request immediately,
regardless of which location handled the command. Recovery delivery and every
read (`clientStatus`, `status`) use the same fresh documents.

Per-chat override writes are now read-merge-write under their own process-wide
lock, so two locations changing different chats cannot drop each other's
override. An unreadable override document fails closed: every chat is treated
as protected instead of following a possibly-`OFF` global.

## What did not change

- The two client globals and the per-chat choice are unchanged.
- Pricing policy, the hold point, the transport guard, recovery, compaction,
  and title handling are unchanged.
- No timer, polling loop, heartbeat, second process, storage format change, or
  queue was added.

## Validation

- New deterministic tests cover a client global changed through another
  location releasing a live hold, a per-chat override changed through another
  location releasing a live hold and appearing in status, and two locations
  preserving each other's overrides.
- Full suite: **148 tests, 0 failures**; lint and typecheck clean; GUI bundle
  rebuilt.

## Install

```sh
opencode plugin add git+https://github.com/lutzkind/opencode-offpeak.git#v0.5.1
```

Desktop must list the same tag in its own `opencode.json(c)` and be restarted.
Desktop 2.3.0+ remains required.
