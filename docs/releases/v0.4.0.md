# v0.4.0 — Independent protection controls, Desktop commands, and real chat names

Released 2026-11-23. Requires OpenCode CLI `>=2.0.26 <2.4.0`; the Desktop GUI
entrypoint requires OpenCode Desktop **2.3.0+** and is validated against 2.3.2.

## What changed

### Two independent global defaults

CLI and Desktop keep separate persistent global protection defaults, both ON.
`/offpeak protection global on|off` changes only the interface that runs it:

- CLI/TUI sends `client: "cli"`.
- Desktop chat sends `client: "desktop"`.
- Neither form can write the other interface's field.

This uses the existing `opencode-offpeak/clients-v1` document. No new service or
configuration system was added.

### One switch per chat

`/offpeak protection chat off` records an explicit bypass for the current
OpenCode session ID. `/offpeak protection chat on` removes it so the chat follows
its relevant global default again. The same entry is written by the Desktop
**Protection for this chat** switch and by the legacy `/offpeak session on|off`
alias. It survives restarts and never changes a global setting or another chat.

### Desktop commands and settings UI

The Desktop GUI entrypoint registers `/offpeak` through the installed GUI SDK's
supported `Command.slash` field. It shares the TUI's command implementation and
supplies the Desktop surface and active session identity. The settings page now
has exactly two controls:

- **Desktop Protection** — the Desktop global default.
- **Protection for this chat** — the routed chat's explicit switch.

The CLI default is read-only on the page. The page also shows the real chat
title, project, shortened session ID, ownership, and effective protection.

### Real Desktop session names

The chat selector uses the canonical OpenCode title from the Desktop's synced
session store, then the project/repository name, then a shortened session ID.
Renames update through OpenCode's own store event. A session missing from the
store is loaded once through the supported session API. Untitled sessions show
**Untitled session**; the full ID remains visible for troubleshooting.

### Queue and safety

Changing a global or chat setting wakes existing interactive holds through the
existing signal/pump and releases a still-waiting verified-peak request in
place. It never re-sends a request, duplicates execution, or drops/reorders a
queue record. Queue-owned tasks never inherit either setting. Invalid or
unreadable client settings still refuse writes and fail closed.

## Install

```sh
opencode plugin add git+https://github.com/lutzkind/opencode-offpeak.git#v0.4.0
```

Desktop users must also list the same tag in Desktop's own `opencode.json(c)`
and run Desktop 2.3.0 or newer.

## Known limitations

- Desktop's brand-new draft has no supported pre-submit registration hook. The
  server still holds an unknown first peak request and releases it when Desktop
  registration arrives; it never sends it unprotected.
- A session opened by both CLI and Desktop remains `ambiguous` and protected
  unless an explicit chat override is set.
- Headless `opencode run` has no client extension and remains `UNKNOWN`
  (protected).
- An interface global OFF cannot be overridden back to ON for one chat without
  enabling that interface's global; `chat on` means "follow the global".
- No OpenCode Desktop application is installed on this host, so Desktop behavior
  is verified through the real packaged GUI bundle and the installed 2.3.2 GUI
  SDK, not by driving an Electron window.
