# v0.3.0 — independent CLI and Desktop protection

Released 2026-11-17.

## Highlights

- **Independent persistent defaults.** `/offpeak client` shows the CLI and Desktop defaults; `/offpeak client cli on|off` and `/offpeak client desktop on|off` change one field each. Both start ON for existing installations, and changing one never writes the other.
- **Native Desktop settings.** The package now exports `./gui-experimental`, built from `src/gui.tsx` into one CommonJS bundle with the official `@opencode/plugin/gui/vite` preset. The page exposes the Desktop switch, the read-only CLI default, the current session's ownership/effective protection, and clear remote-server errors.
- **Supported client identification.** The server request hooks have no client identity. The TUI registers routed sessions as `cli` through the connected server's typed RPC; the GUI registers routed sessions as `desktop` through `SessionRef.server.client`. Registration is additive and idempotent. Unknown sessions and sessions observed by both clients remain protected. No IP/User-Agent/environment guess, heartbeat, lease, polling loop, second database, queue, scheduler, or service was added.
- **Fail-closed first request.** A brand-new Desktop draft cannot be registered before submission through a supported API. Its first peak request is held as `UNKNOWN`, never sent unprotected, and is released when Desktop registration arrives if Desktop protection is OFF. Headless `opencode run` remains unknown and protected.
- **State.** `opencode-offpeak/clients-v1` stores both defaults and per-session ownership. It survives reloads and restarts; `session.deleted` and bounded lazy cleanup remove ownership.

## Compatibility

- Server/TUI: OpenCode `>=2.0.26 <2.4.0` (unchanged).
- Desktop GUI: OpenCode Desktop 2.3.0 or newer.
- Build dependency: `@opencode/plugin@2.3.0`, because the GUI SDK and Vite preset exist only from 2.3.0.

## Install

Server/CLI:

```sh
opencode plugin add git+https://github.com/lutzkind/opencode-offpeak.git#v0.3.0
```

Desktop's own `opencode.json(c)` must list the same package for the GUI page. Installing it only on the remote server does not deploy the local Desktop entrypoint.

## Verification

- `npm run lint`, `npm run typecheck`, `npm test`, and `npm pack --dry-run`.
- Deterministic tests cover independent settings, cross-effect isolation, explicit session overrides, migration with both defaults ON, reload/restart persistence, session-deletion cleanup, unknown/shared fail-closed behavior, GUI RPC targeting, packaged-GUI loading, and unchanged global/queue semantics.
- A real OpenCode 2.3.0 fixture with a local provider and a short simulated peak window proved **0 provider requests** for a protected CLI session until the boundary and exactly **1** for an authorized Desktop session at peak, with the protected request released exactly once at the boundary.
- A real CLI TUI test proved registration of a newly created session, the independent Desktop setting, and the release that follows `/offpeak client cli off`.
- The packaged Desktop GUI bundle was loaded and its setup exercised against fake GUI contexts; the server, TUI, and GUI entrypoints load together without duplicate server initialization.
- Server-side production installation, remote RPC, persistence, and `/offpeak status` are verified separately in the handoff.
