# v0.3.3 — keep the current session on the Offpeak settings page

Released 2026-11-21.

## Fix

OpenCode 2.3.2 defines `Sessions.current()` only while the route shows the
mounted session screen. Opening **Settings > Offpeak** leaves that screen, so
`current()` becomes `undefined`, the page rendered **"No session focused"**, and
the v0.3.2 per-session switch never appeared.

The page now resolves the session in this order:

1. the explicit **Session** pick,
2. the mounted session,
3. the active shell tab (`ctx.tabs.list()`),
4. the last routed session (remembered by the plugin),
5. the only open session.

When several sessions are open on the selected server, a **Session** selector
lists them. **No session open** appears only when no shell tab owns a session;
sessions on another server get **No session open on this server**.

## Server default

The page now prefers the server that owns the resolved session. With no session
it uses the Desktop's own local server, then a single-server session set, instead
of an arbitrary remote. This removes the intermittent
"The Offpeak server could not be reached" state.

## Compatibility

- Server/TUI: OpenCode `>=2.0.26 <2.4.0` (unchanged).
- Desktop GUI: OpenCode Desktop 2.3.0 or newer (unchanged).
- Build dependency: `@opencode/plugin@2.3.2` (unchanged).
- No configuration or storage change when upgrading from `v0.3.2`; the
  `session-overrides-v1` entries and both client defaults are untouched.

## Install

Server/CLI:

```sh
opencode plugin add git+https://github.com/lutzkind/opencode-offpeak.git#v0.3.3
```

Desktop (its own `opencode.json(c)`):

```jsonc
{
  "plugins": ["git+https://github.com/lutzkind/opencode-offpeak.git#v0.3.3"]
}
```

A bare git-tag install still omits the prebuilt `dist/gui-experimental.cjs`; if
the Offpeak page does not appear, use a local checkout of the tag and run
`npm ci && npm run compile`.
