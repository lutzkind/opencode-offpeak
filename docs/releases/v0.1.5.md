# opencode-offpeak v0.1.5

Automatic chat titles are restored, and a title request that is held for peak pricing can no longer be lost.

## Why titles stopped working

OpenCode prepares automatic session naming as its own `title` model request. That request does not use the session model: it uses the provider's *small* model, and for `opencode-go` that is `gpt-6-luna`. The built-in policy only listed the DeepSeek models, so every title request evaluated as `UNKNOWN` for a configured provider and failed closed — at every hour, not only during peak. The result was a successful session with no automatic name, from the moment the plugin was installed.

The Go pricing table lists Off-Peak/Peak tiers only for the DeepSeek models. Every other documented Go model has a single all-hours price.

## What changed

- **`flatModels` in the policy schema.** Each policy can declare the provider's documented all-hours-priced models (explicit globs). They are `OFF_PEAK` at every hour and are never held or blocked. `models` keeps precedence if a pattern matches both, and any model that matches neither list still fails closed — an unlisted future model cannot silently gain peak traffic. The built-in `deepseek-opencode-go` policy lists the documented Go flat models, and an unmodified stored copy of the built-in policy adopts the list at read time, so existing installations pick it up without editing `offpeak.json`.
- **Pending-title recovery.** A held `title` request persists a small `pending-title` marker (session ID, provider/model, location, timestamp, origin) instead of disappearing with the in-memory hold. A session can hold a primary continuation and a title marker at the same time; v0.1.4 stored only one recovery entry per session, so a held title could shadow a primary deferral.
- **Recovery is a check, not a replay and not a mutation.** At the allowed window, a session that already has a title — generated by OpenCode, generated concurrently, or renamed by the user — clears the marker without any request. A session that still needs a title is left to OpenCode's own generation: every path that loses a title hold (inactivity, supersede, shutdown, reload) also resumes the session, and that input promotion is OpenCode's native naming trigger. The marker waits for the title and clears when it appears.
- **No title is ever overwritten or generated twice.** The plugin never calls `session.update` for titles. OpenCode 2.0.27's plugin host renames the session to an *empty* title for `{ title: "" }` (unlike the HTTP handler, which regenerates), and this pass proved that live in a fixture run; the delivery therefore mutates nothing.
- **Kind-aware transport cleanup.** The `http.request`/WebSocket guard now sees the request kind and removes only its own recovery class: a released title clears a pending title, a released primary clears a primary continuation, and neither can clear the other.

## What is unchanged

- Peak protection: a peak-priced request still never crosses the provider transport during a blocked window, `UNKNOWN` still fails closed for every request kind, and `OFF`/`queue`/`guard`/`run-now` semantics are untouched.
- The v0.1.4 pre-model deferral, the v0.1.3 cross-boundary retry recovery, the persistence of primary deferrals across reload/restart, and the Chinese public-holiday calendar.

## Evidence

- Unit suite: 86 tests (`npm run lint`, `npm run typecheck`, `npm test`), including flat-model pricing at peak hours, overlap precedence, ambiguous/invalid lists failing closed, pending-title persistence and cleanup semantics, and read-time policy adoption.
- Real OpenCode 2.0.27 + local fixture provider (no paid traffic):
  - live-shaped config under v0.1.4: title request for `opencode-go/gpt-6-luna` blocked, session left untitled, one provider request total;
  - the same config under v0.1.5: the flat list is adopted from the stored copy, the title request is allowed, one title generated;
  - PEAK window with a covered title model: zero provider traffic while blocked, `pending-title` + `deferred` markers persisted together, both released at the boundary, one title and one primary request;
  - PEAK + `opencode reload`: markers persisted, one title and one primary request at the boundary, no duplicate prompt;
  - PEAK + full server restart: markers persisted, exactly one continuation and exactly one native title request after the boundary, one session, recovery state clean;
  - uncovered title model: still fails closed with zero provider traffic.
- Installed live path: `opencode plugin add git+https://github.com/lutzkind/opencode-offpeak.git#v0.1.5`, `/offpeak status` ON/`auto`, queue and recovery clean.

## Installation

```sh
opencode plugin add git+https://github.com/lutzkind/opencode-offpeak.git#v0.1.5
```

Requires OpenCode CLI v2 `>=2.0.26 <2.1.0` (validated on 2.0.27).
