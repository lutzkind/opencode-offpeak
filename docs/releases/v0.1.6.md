# opencode-offpeak v0.1.6

Direct DeepSeek API support, verified OpenCode Zen semantics, and immediate non-chat feedback when a request is held for off-peak pricing.

## Provider support matrix

| Provider | Time-based protection | Covered model IDs | Source (verified 2026-10-15) |
|---|---|---|---|
| OpenCode Go (`opencode-go`) | Yes — peak-deferred | `deepseek-v4.1-flash`, `deepseek-v4-pro`, `deepseek-v4-flash`, `deepseek-v4-flash-vision-exp` (peak-priced); all other documented Go models are `FLAT` (never wait) | https://opencode.ai/docs/go/ |
| Direct DeepSeek API (`deepseek`) | Yes — peak-deferred | `deepseek-flash`, `deepseek-v4-pro` (canonical API models) and the legacy aliases `deepseek-v4-flash`, `deepseek-v4-flash-vision-exp` (still accepted, billed at the Flash price) | https://api-docs.deepseek.com/quick_start/pricing |
| OpenCode Zen (`opencode`) | No waiting required — flat pricing | No policy by design: every model has one all-hours price with no peak/off-peak tiers, so requests are never delayed or blocked | https://opencode.ai/docs/zen/ |

Both peak-priced policies share the same verified rule: **peak** Monday–Friday 01:00–04:00 and 06:00–10:00 UTC; **off-peak** all other hours, weekends, and Chinese statutory public holidays in full (shared 2026 State Council calendar).

Unknown or newly released model IDs under a peak-priced provider are **not guessed**: they evaluate `UNKNOWN` and fail closed with an actionable message until a verified policy update ships. There is no `deepseek-*` wildcard. `opencode` (Zen) has no policy at all, so a new Zen model is never blocked merely because a DeepSeek policy exists for another provider.

## Held-request feedback

A primary interactive request that enters a PEAK hold now announces itself exactly once:

```
OpenCode Offpeak
Peak pricing active — request held until 08:00 Asia/Bangkok. It will resume automatically in this session.
```

and at the boundary (or when a persisted recovery continues the session):

```
OpenCode Offpeak
Off-peak pricing started. Resuming the held request in this session.
```

- Delivered as plugin RPC events on OpenCode's own event stream and rendered by the TUI entrypoint as toasts — never a chat message, never model context, and never in headless output.
- The deadline uses the configured `displayTimeZone`, so it is never hard-coded.
- Exactly one `hold` and at most one `resume` per held request; a reload or restart cannot duplicate them, a user cancel produces no false resumption, auxiliary `title`/`compaction`/`generate` holds are silent, and queue-owned sessions keep their existing queue/status semantics.
- Headless `opencode run` stays silent: no subscriber exists, stdout is untouched.

## Curated details

- **`FLAT` pricing state.** A model with a vendor-documented all-hours price now reports `FLAT`: allowed, never waits, no next transition. `/offpeak status` shows `Pricing: FLAT`, and for Zen `Pricing: UNTRACKED` with `Requests: ALLOWED (no policy needed: …)`.
- **Adoption for existing installs.** A stored `offpeak.json` that contains only unmodified copies of the shipped policies (what a first toggle persists) gains newly shipped built-in policies at read time — the live install picks up `deepseek-api` without editing the file. A customized policy set is left exactly as written.
- **Actionable failure text.** `deepseek/deepseek-future-model` → "Provider deepseek is configured, but model … is not in the verified off-peak pricing policy for this release. Update opencode-offpeak or add a verified custom policy before using this model."
- **Annual maintenance.** The Chinese holiday calendar in `src/holidays.ts` and the verified model lists in `src/policy.ts` are reviewed each November (and whenever a provider adds a model); `docs/pricing-policies.md` documents the procedure.

## Verification

- `npm run lint`, `npm run typecheck`, `npm test` — **99 tests pass**; `npm pack` validated.
- Real OpenCode 2.0.27 + local fixture provider (no paid traffic, no peak-window provider calls):
  - OpenCode Go shape in a real TUI: hold toast at +0.9s, **zero primary provider traffic during the simulated peak window**, resume toast at the boundary, reply rendered, one session, one user message, automatic title, exactly one primary + one flat title request; `/offpeak status` during the hold showed `Pricing: PEAK`, `Requests: BLOCKED`, `Interactive: 1 request waiting for off-peak`.
  - Direct DeepSeek headless with the server event stream captured: exactly one `rpc.opencode-offpeak.hold` and one `rpc.opencode-offpeak.resume` (`kind: "release"`), both provider requests (title + primary) only at the boundary, clean recovery state, clean stdout, exit 0.
  - Zen: no hold toast, reply inside the simulated peak window, status `UNTRACKED` + verified note.
  - Reload: exactly one hold and one resume, no duplicates. Restart: exactly one hold and one `kind: "continuation"` resume, one continuation, no duplicate original prompt, title generated.
- Known platform race (pre-existing, reproduced identically on v0.1.5): if an `opencode reload` tears down the plugin generation while a released automatic-title request is still in flight, OpenCode's own title commit can be dropped and the session stays untitled until the next prompt. The pending-title marker watches for the title and is dropped with a diagnostic afterwards; the plugin deliberately never mutates a session title.

## Installation

```sh
opencode plugin add git+https://github.com/lutzkind/opencode-offpeak.git#v0.1.6
```

Requires OpenCode CLI v2 `>=2.0.26 <2.1.0` (validated on 2.0.27).
