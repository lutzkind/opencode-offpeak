# v0.5.0 — Simple peak-price protection

## What changed

v0.5.0 reduces `opencode-offpeak` to the model users actually asked for:

- one global switch per client: **CLI Protection** and **Desktop Protection**;
- one per-chat choice: **follow global**, **always protect**, or **allow peak**.

An explicit chat choice wins over both globals. A chat that is protected waits
for off-peak and continues automatically; a chat that is allowed runs at
verified peak prices immediately. Unknown models and invalid configuration
still fail closed.

## Removed

- The global `enabled` toggle and its misleading "OFF still blocks" behavior.
- The `auto` / `queue` / `guard` execution modes.
- The background task queue and every queue command (`queue`, `list`,
  `cancel`, `remove`, `retry`, `resume`, `run-now`).
- First-client-wins `ambiguous` ownership. A chat now follows the client that
  most recently opened it.

Existing queue storage is preserved but unused. Legacy `enabled`/`mode` fields
in `offpeak.json` are accepted and ignored. Existing `"off"` chat overrides
keep their meaning.

## Commands

```text
/offpeak
/offpeak on | off
/offpeak chat on|off|auto
/offpeak cli on|off
/offpeak desktop on|off
```

The Desktop settings page exposes the same three controls: CLI Protection,
Desktop Protection, and Off-peak protection for this chat.

## Desktop

Desktop must list the same tag in its own `opencode.json(c)`; installing the
package only on the remote server does not load the local GUI. Desktop 2.3.0+
is required. The page now retries a startup RPC briefly, so a freshly started
Desktop SSH server no longer leaves it stuck on an error.

## Validation

- Full deterministic suite: 145 tests, 0 failures.
- Lint, typecheck, `npm pack --dry-run`, and the committed GUI bundle rebuild
  are clean.
- The real-TUI fixture still loads the packed plugin, registers the CLI
  session, and releases the held request when CLI protection is switched off.
