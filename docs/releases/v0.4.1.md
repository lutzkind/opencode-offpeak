# v0.4.1 — Cross-location protection defaults

Released 2026-11-23. Requires OpenCode CLI `>=2.0.26 <2.4.0`; the Desktop GUI
entrypoint requires OpenCode Desktop **2.3.0+** and is validated against 2.3.2.

## Fix

OpenCode can load the server plugin once per project/location in the same
process. Each location had its own engine with an in-memory snapshot of the
shared `opencode-offpeak/clients-v1` document. A stale location could persist
its old defaults while registering a session and revert a setting changed in
another location. Live verification caught Desktop Protection reverting to OFF
after CLI sessions loaded in a different directory.

Client-default and ownership writes now:

- read the latest stored document under a process-wide lock,
- apply only the changed field or session, and
- never write a whole stale snapshot.

Every protection decision, status read, and client-status read refreshes the
stored document first. An unreadable document still fails closed: both defaults
become ON, ownership is cleared, and writes are refused.

## Verification

- `npm run check`: lint, typecheck, **175 tests, 0 failures**.
- New deterministic two-engine test: the second location starts before the
  first changes Desktop Protection, sees the change on its next guard, and a
  later stale session registration preserves the newer value.
- Live: CLI ON / Desktop ON after independent toggles; a per-chat override
  verified at peak with both global defaults unchanged.

## Install

```sh
opencode plugin add git+https://github.com/lutzkind/opencode-offpeak.git#v0.4.1
```

Desktop users must also list the same tag in Desktop's own `opencode.json(c)`
and run Desktop 2.3.0 or newer.
